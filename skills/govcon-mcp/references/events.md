# Events and meeting preparation

Start with the user's objective: find relevant industry days, evaluate a conference, prepare for a meeting, or organize follow-up. Use their company, target agencies, topic, location and dates where known. Discover the connected event tools before making calls; event search in the G2X website does not prove the MCP exposes it.

Search with the relevant date, location, virtual and free/paid filters supported by the current schema. Read the selected event's stored details: agenda, speakers, sponsors, organizer, registration link and available business context. Preserve unknown dates, times, time zones and prices. Keep listed attendees separate from likely attendees; sponsorship or a speaker listing does not prove that a specific person will attend.

Use your model to prepare a short plan: why the event fits, relevant sessions, people or organizations to research, questions to ask and useful follow-up. Link the event and evidence. Use [Companies and people](companies.md) to resolve potential partners; do not turn a matching name into a confirmed company or contact. Save a requested brief through [Save work in G2X](work-products.md).

When asked to save an event, check whether the destination is the user's calendar or a shared team calendar. Use an explicit desired-state action when available, then read back the result. Do not blindly retry a toggle after an uncertain response. Team calendar changes can create or archive a shared event-planning workspace; inspect the action's stated effects before changing it. A removal must match the user's intended shared scope.

Saving, exporting or subscribing to an event calendar does not register the user with the organizer. For registration, use the official returned registration link and the user's authorized browser workflow. Keep private calendar subscription links out of public documents and shared briefs.

After the event, turn the user's supplied notes into proposed relationship updates and next steps. Use [GovCon CRM](crm.md) for requested saves. An event plan does not authorize sending outreach, inventing a completed meeting, purchasing a ticket or scheduling future monitoring.
